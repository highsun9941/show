# 한 컷, 한 마디

영화·드라마·애니메이션·예능·교양의 **이미지 한 장을 보고 대사를 맞히는** 행사 진행용 웹 프레젠테이션입니다. 아이패드와 노트북에서 주소만 열면 플레이할 수 있습니다.

**사이트 주소:** `https://<복제한 계정>.github.io/<복제한 저장소>/` (아래 Pages 설정 후 이용)

## 가장 먼저 할 일: GitHub Pages 켜기

1. **복제한 저장소의 Settings → Pages**로 이동합니다.
2. **Build and deployment → Source → GitHub Actions**를 선택합니다.
3. 같은 저장소의 **Actions → Check and deploy GitHub Pages**를 열어 **Run workflow → 기본 브랜치 → Run workflow**를 누릅니다. 기본 브랜치는 보통 `main`이며 `master` 등 다른 이름도 지원합니다. 이미 성공한 실행이 있다면 생략합니다.
4. 초록색으로 완료되면 위 사이트 주소를 엽니다. 이후 기본 브랜치에 저장하면 자동 배포됩니다.

별도 서버, Cloudflare, 데이터베이스, npm 패키지 설치가 필요하지 않습니다. `docs/`가 웹사이트 전체입니다. Actions를 쓰지 않을 경우 Source를 **Deploy from a branch → 기본 브랜치 → /docs → Save**로 설정해도 됩니다. 두 방식 중 하나만 선택하세요.

## 다른 계정·다른 이름의 저장소로 복제하기

**이 버전은 원본 계정이나 `show`, `main`이라는 이름에 의존하지 않습니다.** 공개 저장소를 Fork하거나, clone한 코드를 새 공개 저장소에 push한 뒤 위 Pages 설정을 진행하면 됩니다. 컴퓨터로 clone만 하는 것은 로컬 복사이므로, 다른 사람에게 주소를 공유하려면 새 GitHub 저장소에 push하고 Pages를 켜야 합니다.

1. **새 저장소를 공개(Public)**로 준비합니다. GitHub 무료 계정에서 공개 Pages와 로그인 없는 이미지 접근을 사용하는 구성입니다.
2. Fork했다면 새 저장소의 **Actions**에서 워크플로 활성화 안내가 나올 수 있습니다. 안내를 확인해 활성화합니다. **Pages 설정과 토큰은 Fork/clone으로 복사되지 않습니다.**
3. 새 저장소에서 위 **Pages 켜기**를 진행합니다. Actions 배포는 현재 계정·저장소·배포 브랜치를 `deployment.json`에 자동으로 넣습니다. `config.js`를 수정할 필요가 없습니다.
4. **새 저장소 소유자**가 **새 저장소만 선택한 저장용 키**를 발급합니다. 로그인 아이디 `이젠`, 비밀번호 `ezen`은 동일합니다.
5. 새 Pages 주소에서 **문제 보관함**을 열고, 저장 안내에 **새 계정/새 저장소**가 표시되는지 확인합니다. 문제를 하나 추가한 뒤 새 저장소의 `docs/data/questions.json`과 `docs/uploads/`에 저장됐는지 확인합니다.

표준 `github.io` 주소에서 브랜치 직접 배포를 사용해도 주소로 현재 저장소를 감지하고 GitHub API로 기본 브랜치를 찾습니다. GitHub Actions 방식은 `main` 이외의 기본 브랜치도 지원합니다. 저장소 이름이 `<계정>.github.io`인 계정 홈페이지도 지원합니다.

**사용자 지정 도메인:** GitHub Actions 배포라면 자동 배포 정보로 동작합니다. Actions 없이 브랜치 직접 배포하는 사용자 지정 도메인이나 로컬 개발에서 공동 편집을 쓰려면 `docs/config.js`의 `repository`에 `'내계정/내저장소'`를 지정하세요. 기본 브랜치 이외에 저장하려면 `branch`도 지정합니다. 원본 저장소 주소를 그대로 넣지 마세요. 로컬에서 설정하지 않아도 배포된 샘플 플레이와 기기 체험 모드는 사용할 수 있습니다.

**이미지까지 독립적으로 복제하려면:** `docs/uploads/` 파일도 함께 복사하세요. 이 버전에서 웹사이트로 올린 이미지는 `./uploads/…`로 저장되므로 복제본의 이미지를 읽습니다. 외부 HTTPS 주소로 등록한 이미지는 외부 자료를 계속 참조하며 자동 복사되지 않습니다. 이전 버전의 원본 저장소 raw 주소도 같은 방식이므로, 해당 이미지 파일을 새 저장소에 복사하고 `image`를 `./uploads/파일명`으로 바꿔주세요.

브라우저의 기기 체험 데이터와 저장 방식은 사이트 주소별로 분리됩니다. GitHub 저장용 키도 저장소·브랜치별로 분리되며 새 저장소로 자동 전달되지 않습니다.

## 문제를 함께 편집하는 방법

10명 이내의 단기 사용을 위한 간단한 구성입니다.

- **플레이:** 주소만 접속합니다. 로그인·GitHub 계정·저장용 키가 필요 없습니다.
- **문제 관리:** `문제 보관함 → 문제 관리`에서 아이디 **`이젠`**, 비밀번호 **`ezen`**, 아래에서 만든 **저장용 GitHub 키**를 입력합니다.
- 각 편집 기기는 그 키를 이 브라우저 탭의 세션에 기억합니다. **관리 종료**를 누르면 지웁니다. 참여자 각자의 GitHub 계정은 필요 없습니다.
- 추가·수정·삭제는 `docs/data/questions.json`에 커밋으로 기록됩니다. 이미지 선택 시 자동으로 줄여 `docs/uploads/`에 올립니다. 다른 기기는 **↻ 새로고침**을 눌러 최신 문제를 읽습니다.
- 같은 문제를 동시에 수정하면 뒤늦은 저장을 중단합니다. 입력 내용을 복사한 뒤 편집 창을 닫고 새로고침해 다시 수정하세요. 서로 다른 문제의 변경은 최신 목록에 합쳐 저장합니다.

아이디·비밀번호는 간단한 관리 화면 입장용이며 소스에 공개됩니다. **실제 GitHub 쓰기 권한은 저장용 키가 담당합니다.** 키는 `config.js`, 저장소 파일, URL에 넣지 말고 웹사이트 로그인 창에서 입력하세요.

### 저장용 키 준비 (소유자가 한 번만)

1. [GitHub → Fine-grained personal access tokens → Generate new token](https://github.com/settings/personal-access-tokens/new)을 엽니다.
2. 이름은 `show-game`, 만료는 행사 종료 후 가까운 날짜로 정합니다.
3. **Resource owner:** 복제한 저장소를 소유한 계정이나 조직을 선택합니다.
4. **Repository access → Only select repositories**에서 **복제한 저장소만** 선택합니다. 원본 저장소용 키는 복제본에 쓰기 권한을 주지 않습니다.
5. **Repository permissions → Contents → Read and write**를 설정합니다. Metadata의 Read는 기본으로 포함됩니다.
6. 발급된 `github_pat_…` 키를 보관하고 문제를 편집할 사람에게만 직접 공유합니다. 키를 이 채팅이나 공개 저장소에 올릴 필요는 없습니다.
7. 행사가 끝나면 같은 GitHub 설정에서 키를 삭제합니다.

공개 저장소이므로 이미지와 정답도 공개 자료입니다. 현재 접속된 사람에게 실시간으로 화면을 보내는 기능은 없습니다. 진행자가 자기 화면을 디스플레이에 연결하거나 미러링해 진행하는 방식입니다.

## 화면 모드

화면은 흰색·검은색 중심의 라이트/다크 모드를 지원합니다. 처음에는 기기의 화면 모드를 따르고, 상단의 해·달 버튼으로 바꿀 수 있습니다. 직접 고른 모드는 다음 접속에도 유지됩니다. 게임 진행 화면에서도 같은 버튼을 사용할 수 있습니다. 문제 이미지의 원래 색상은 유지합니다.

휴대폰·태블릿·노트북·데스크톱에서 화면 폭에 맞춰 메뉴, 게임 설정, 보관함과 편집창이 재배치됩니다. 작은 화면은 카드를 한 열로 보여주며, 터치 버튼과 입력 글자를 크게 표시합니다. 게임 이미지는 잘리지 않고 전체가 보이고, 긴 힌트·정답과 편집창은 안쪽으로 스크롤할 수 있습니다. 가로·세로 전환과 화면의 안전 영역도 반영합니다.

반응형 배치는 브라우저에서 320×568부터 1920×1080까지 20가지 화면 크기로 점검했습니다. 실제 기기의 브라우저 버전이나 전체 화면 지원 여부까지 모든 조합을 검증한 것은 아닙니다.

## 게임 진행

1. **플레이룸**에서 카테고리, 문제 수, 제한 시간을 고릅니다.
2. **게임 시작하기**를 누릅니다. 게임 안에서는 중복 없이 출제하며, 등록된 문제가 적으면 있는 만큼 진행합니다.
3. 장면을 보여주고 참가자의 답을 받습니다. 제한 시간을 선택했다면 장면이 뜬 뒤 **타이머를 직접 시작**합니다.
4. **힌트**를 누르면 해당 장면의 **작품 제목**이 공개됩니다. 다시 누르면 숨깁니다. **정답 공개 / 다음 문제**를 누르며 진행합니다. 타이머 종료 시 정답을 자동 공개하지 않습니다.
5. 전체 화면 버튼 또는 `F`를 사용합니다. iPad Safari의 전체 화면 지원은 기기·버전에 따라 다르며, 지원되지 않아도 터치로 플레이할 수 있습니다.

| 키 | 동작 |
| --- | --- |
| Space | 정답 공개·숨김 |
| ← / → | 이전·다음 문제 |
| H | 작품 제목 힌트 공개·숨김 |
| T | 타이머 시작·일시정지 |
| F | 전체 화면 |
| Esc | 전체 화면 해제 / 대화상자 닫기 |

타이머는 탭을 벗어나거나 대화상자를 열면 멈춥니다. 현재 게임은 시작할 때 뽑은 문제를 유지하며, 다른 사람의 편집은 다음 게임부터 반영합니다.

### 회차별 플레이 기록

**게임 시작하기** 또는 **다시 섞어서 플레이**로 시작한 게임을 끝까지 마치거나 **게임 종료 → 종료하고 기록 저장**을 누르면, **실제로 화면에 표시한 문제만** 기록합니다. 미리 불러온 다음 이미지나 아직 보지 않은 문제는 포함하지 않고, 이전 문제로 돌아가 다시 본 장면도 한 번만 남깁니다.

문제 보관함의 이미지를 누르면 **문제 미리보기**로 열립니다. 힌트와 정답을 확인한 뒤 **문제 보관함으로** 돌아갈 수 있으며, 미리보기는 플레이 기록을 만들거나 회차 번호를 올리지 않습니다. 닫으면 보관함의 페이지·검색·분류·스크롤 위치를 유지하고, 방금 열었던 카드로 포커스를 돌려놓습니다.

종료 화면의 **이번 회차 기록 보기** 또는 상단 **플레이 기록**에서 회차를 선택하세요. 시작 시각, 완주·중도 종료 여부, 출제 번호, 이미지, 당시 작품명과 대사를 볼 수 있습니다. 보관함에서 나중에 대사나 제목을 수정해도 이전 기록은 바뀌지 않습니다. 이미지는 기존 원본 파일을 참조하므로 GitHub·외부 이미지를 볼 때는 인터넷 연결이 필요합니다.

각 회차 상세 화면의 **N회차 이미지 내보내기**를 누르면 그 회차에 나온 이미지만 ZIP으로 받습니다. 이미 저장해 둔 회차에서도 사용할 수 있으며, 파일명은 기록 당시의 **작품명 - 대사.확장자**, ZIP 이름은 **한컷한마디-N회차-이미지-게임시작날짜.zip**입니다. 원본 이미지 형식과 화질을 유지합니다. 내보내는 도중 다른 회차를 선택해도 처음 누른 회차의 파일을 받으며, 일부 실패 시 같은 회차의 실패한 이미지만 다시 받을 수 있습니다.

최근 **10회차**를 이 브라우저에 보관합니다. 11회차를 저장하면 1회차가 삭제되고, 회차 번호는 계속 이어집니다. 기록은 GitHub·기기 저장 모드 모두 **로컬 IndexedDB**에만 남으며 다른 기기·브라우저나 다른 사이트 주소로 공유되지 않습니다. 새로고침 후에도 유지되지만 브라우저 사이트 데이터를 삭제하면 사라집니다. 진행 중 새로고침하거나 탭을 닫은 게임은 저장하지 않으므로, 먼저 게임 종료를 눌러 주세요. 저장 실패 시 종료 화면에서 다시 시도할 수 있습니다.

## 약 1,000개 문제 준비하기

촬영 후 편집에 쓸 이미지는 **문제 보관함 → 이미지 전체 내보내기**에서 ZIP으로 내려받을 수 있습니다. 관리자 로그인 없이 사용할 수 있으며, 검색·분류·현재 페이지와 관계없이 보관함의 모든 문제 이미지를 포함합니다. 파일명은 **작품명 - 대사.확장자**입니다. 원본 파일의 화질과 형식을 유지하고, 게임 화면에서 덧씌우는 자막 가림은 파일에 합성하지 않습니다.

여러 줄 대사는 파일명에서 한 줄로 합치고 파일명에 쓸 수 없는 문자는 공백으로 바꿉니다. 같은 이름이 겹치면 `(2)`, `(3)`을 붙입니다. 매우 긴 이름은 줄이되 ZIP 안의 `전체 파일명과 대사.txt`에 전체 내용을 보관합니다. 다운로드 중 취소할 수 있으며, 일부 이미지에 실패하면 개수를 표시하고 실패 목록과 **실패한 이미지 다시 받기**를 제공합니다. 외부 사이트 이미지의 경우 해당 사이트가 파일 다운로드를 허용해야 받을 수 있습니다.

이 프로젝트의 창작 일러스트·창작 대사 샘플은 게임 방식 체험용입니다. 등록하거나 가져온 영화·드라마·애니메이션·예능·교양 문제가 같은 보관함에 표시됩니다. 체험용 샘플은 관리 화면에서 삭제할 수 있습니다.

### 하나씩 등록

**문제 관리 → 문제 추가**에서 이미지 파일, 작품명, 분류, 정답 대사를 넣습니다. 연도·출처는 함께 기록할 수 있습니다. 힌트는 입력한 작품명으로 자동 제공되므로 따로 작성하지 않습니다. 이미지는 원본 비율을 유지해 가로·세로 최대 1,600px 및 300KB 이내로 줄입니다. 게임 화면에서는 자르지 않고 전체 이미지를 보여줍니다.

### 한꺼번에 등록 (CSV / JSON)

1. [CSV 양식](docs/data/import-template.csv)을 내려받아 스프레드시트에서 작성합니다. 예시 행은 삭제하고 실제 내용으로 채우세요. **UTF-8 CSV**로 저장합니다.
2. 이미지 파일을 GitHub의 `docs/uploads/`에 미리 올리거나, 직접 열 수 있는 HTTPS 이미지 주소를 준비합니다. 저장소에 올린 이미지는 다음처럼 **저장소 내부 경로**로 적습니다. 이 방식이면 나중에 다른 저장소로 복제해도 이미지가 함께 동작합니다.

   `./uploads/scene-001.jpg`

3. 사이트의 **가져오기**에서 CSV 또는 JSON을 선택합니다. 1,000개 메타데이터도 한 번의 커밋으로 저장합니다. 전체 입력을 먼저 검사하므로 잘못된 행이 있으면 행 번호를 알려줍니다.
4. **고유한 id가 같은 문제는 건너뜁니다.** 가져오기는 기존 문제를 덮어쓰지 않습니다. 같은 파일을 재시도할 때 중복되지 않도록 id를 꼭 채워주세요. id를 비우면 매번 새로 생성됩니다.

| 열 | 내용 | 필수 |
| --- | --- | --- |
| `id` | 고유 ID, 예: `movie-0001` (영문·숫자·`-`·`_`, 80자 이내) | 권장 |
| `title` | 작품명 (150자 이내) | O |
| `category` | `국내 영화`, `해외 영화`, `국내 드라마`, `해외 드라마`, `국내 애니메이션`, `해외 애니메이션`, `국내 예능`, `국내 교양`, `국내 만화`, `해외 만화`, `국내 뉴스`, `기타 밈` | O |
| `answer` | 정답 대사 (2,000자 이내, 여러 줄 가능) | O |
| `image` | `./uploads/파일명.jpg` 또는 바로 열 수 있는 HTTPS 이미지 주소 | O |
| `year` | 네 자리 연도 | 선택 |
| `source` | 이미지 출처·메모 (1,000자 이내) | 선택 |
| `imageMasks` | 자막 가림 영역 배열. 각 항목의 `x`, `y`, `width`, `height`는 원본 사진 기준 0~1 좌표이며 최대 8개입니다. CSV에서는 JSON 문자열로 지정합니다. | 선택 |
| `enabled` | `true` 출제 / `false` 출제 제외 (기본 `true`) | 선택 |

이전 자료에 `hint`가 있어도 불러올 수 있으며, 게임에서는 항상 작품명을 힌트로 표시합니다. 이전 분류 `영화`·`드라마`·`애니메이션`도 불러올 수 있지만, 국내·해외를 임의로 정하지 않고 **전체**에서만 출제합니다. 문제 수정 화면에서 지원하는 분류 중 하나를 선택하면 해당 카테고리에도 나옵니다.

예능 장면은 `국내 예능`, 시사·교양 프로그램의 장면은 `국내 교양`으로 선택할 수 있습니다.
만화 컷은 `국내 만화`·`해외 만화`, 뉴스 장면은 `국내 뉴스`로 선택합니다. 원작이나 제작 국가를 확인하지 못한 인터넷 짤은 `기타 밈`으로 분류하고, 작품명을 추측해서 입력하지 않습니다.

JSON은 문제 배열 `[{...}, {...}]` 또는 `{"questions": [{...}]}` 형식입니다. 전체 문제 최대 5,000개를 지원합니다. 목록은 24개씩 표시하고 게임은 다음 한 장만 미리 읽으므로 1,000개 이미지를 한꺼번에 내려받지 않습니다.

**준비할 자료:** 사용할 장면 이미지, 작품명, 그 장면의 정확한 정답 대사. 정답이 이미지 자막에 이미 보이는 장면은 피해 주세요.

## 내보내기와 기기 체험 모드

- **JSON 내보내기:** 현재 전체 문제 목록을 내려받습니다. GitHub 모드의 이미지는 저장소 내부 경로 또는 외부 주소로 기록됩니다. 실제 이미지까지 보관하려면 저장소도 다운로드하세요. 문제를 삭제해도 업로드 이미지 파일은 다른 문제나 이전 게임에서 사용할 수 있어 남겨둡니다.
- 우측 상단 **GitHub에 저장 → 이 기기에만 저장**을 고르면 로그인 없이 모든 관리 기능을 체험할 수 있습니다. 이 모드는 다른 기기와 공유되지 않습니다. 브라우저 데이터 삭제 시 사라지므로 필요한 문제는 먼저 내보내세요.
- 기기 모드에서 내보낸 JSON에는 업로드 이미지도 포함됩니다. 이미지가 내장된 JSON은 기기 모드로 가져올 수 있으며, GitHub 일괄 가져오기에는 `./uploads/파일명` 또는 HTTPS 이미지 주소를 사용합니다.
- GitHub 공개 API의 요청 한도나 연결 문제가 있으면 플레이 화면은 마지막 Pages 배포본을 사용하며 보관함에 안내합니다. 저장용 키로 로그인하면 인증된 요청으로 읽고 저장합니다.

## 개발 및 검증

Node.js 22.13 이상에서 추가 패키지 없이 실행합니다.

```sh
npm run dev
npm run check
npm test
```

개발 주소: `http://localhost:3000`. 파일을 직접 더블클릭하는 `file://` 모드는 모듈·데이터 로딩을 지원하지 않습니다.

- `docs/index.html`, `docs/styles.css`: 반응형 화면
- `docs/js/app.js`: 게임·관리·타이머·키보드 조작
- `docs/js/play-history.js`: 실제 출제 장면 기록·로컬 회차 저장·최근 10회차 유지
- `docs/js/theme.js`: 초기 화면 모드·테마 전환·선택 저장
- `docs/js/storage.js`: GitHub 직접 저장 / IndexedDB 기기 저장
- `docs/js/core.js`: 문제 검사·CSV 파싱·필터·랜덤 출제
- `docs/config.js`: 자동 감지 / 필요할 때만 명시하는 공개 설정 (토큰 저장 금지)
- `docs/js/config.js`: Pages 주소·배포 정보로 저장소와 안내 링크 결정
- `docs/deployment.json`: Actions가 배포본에만 현재 저장소·브랜치를 기록
- `.github/workflows/pages.yml`: 검증 후 Pages 배포

공식 참고: [GitHub Contents API](https://docs.github.com/en/rest/repos/contents), [GitHub Pages 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).
